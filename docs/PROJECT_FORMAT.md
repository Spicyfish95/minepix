# `.pix` 二进制格式

PIX 是 MinePix 的分块压缩二进制项目格式。ASE / Aseprite 是独立的交换格式。

## 文件布局

所有整数使用小端编码。文件依次为 32 字节文件头和若干分块，第一块必须为 `META`，随后为 `DATA`。

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 8 | 魔数 `MINEPIX\0` |
| 8 | 2 | 容器版本，当前为 1 |
| 10 | 2 | 文件标志，当前为 0 |
| 12 | 4 | 文件头长度，当前为 32 |
| 16 | 8 | 完整文件长度 |
| 24 | 4 | 分块数量，包含 META |
| 28 | 4 | 前 28 字节的 CRC32 |

每块的头长 20 字节：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | ASCII 类型：META / DATA |
| 4 | 4 | 块标志，当前 1 表示 zlib |
| 8 | 4 | 压缩字节数 |
| 12 | 4 | 原始字节数 |
| 16 | 4 | 原始内容 CRC32 |

`META` 解压后为 UTF-8 JSON，包含 `document` 和 `blocks`。图层、帧时长、标签、混合模式、cel 属性、链接、色板、切片和布局相关作品信息留在 document。像素数组与参考图数据的位置使用 `null` 占位。

blocks 按 DATA 块顺序记录：

- `path`：对应 document 内占位符的 JSON Pointer。
- `kind`：`u32` 为 RGBA 像素整数；`u8` 为索引像素；`base64` 为参考图的原始 RGBA 字节，加载后回填为前端使用的 Base64。
- `count`：像素元素数量或字节数量。

像素不再以 JSON 数字字符串保存。每个 cel 独立压缩，便于后续做局部读取；当前实现完整加载文档。CRC32 用于损坏检测，不用于身份验证。

## 边界与版本

文件和累计解压数据分别限制为 512 MiB。读取时检查魔数、版本、长度、块标志、校验和、映射和数据长度。未知版本明确拒绝，避免静默丢失内容。

编辑器另外执行作品语义容量限制：逻辑画布像素为宽×高×图层数×帧数，实际 cel 像素为所有帧各 cel 源图长度之和；两者各加独立参考与参考图层的原始图片像素后均不得超过 32M。链接 cel 按每帧计数，组 / 参考图层仍计入逻辑画布；最多 64 层、256 帧。打开与增加容量的编辑操作使用同一规则。32M 是像素预算，独立于上述 512 MiB 容器限制，不代表前端 JavaScript 峰值内存为 128 MiB。

地形预览还使用独立的渲染输出预算：格子数乘图块尺寸后最多8M像素、单边8192。此为界面渲染限制，超限预览的合法元数据仍可载入和保存，作品内容不丢弃；面板提示缩小尺寸后继续编辑。

容器版本与编辑器内存对象的版本分开。内存对象只用于前端交互与 Rust 调用，不承诺为对外项目格式。

## 实施与验证

实现位于 src-tauri/src/project.rs，使用 fast 压缩级别。验证命令见 [开发指南](DEVELOPMENT.md)。

正常保存使用独立的原始字节IPC：`MPXSAVE1`八字节标记、u32元数据长度、UTF-8 `{document,blocks,name,saveAs}`、顺序拼接的原始像素块。前端直接从当前文档对象打包，只序列化小元数据，不再先生成 / 解析整作品JSON；Rust仅解析小元数据，借用payload直接压缩，不再为每个像素建立JSON Value。打包不修改源文档或链接cel共享关系；字符串输入保留用于既有诊断，性能报告明确区分这两条参数准备路径。此IPC不是磁盘文件格式，对外仍是上述PIX v1。跨语言固定样例和实际索引 / 链接 / 参考 / 稀疏cel保存已验证与原编码器输出逐字节一致，中文目标名称、取消和失败不覆盖沿用原语义。

正常PIX读取先返回实际路径描述符，再由Rust专用命令读取并共用原容器校验，成功后才更新最近记录。响应为`MPXREAD1`八字节标记、u32小JSON元数据长度、UTF-8 `{document,blocks}`以及顺序原始像素块；没有新磁盘版本。前端解包为普通数组，通过file.document直接交给模型标准化。file.data仅为按需生成的诊断JSON，正常打开 / 最近缩略图不访问；缩略图读取也不重排最近记录。原生打开、启动队列、第二实例和拖入共用此路径，单个损坏启动项目报错后继续处理后续文件。恢复读取仍保留原链路。
