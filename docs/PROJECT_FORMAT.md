# `.pix` 二进制格式

PIX 是 MinePix 的分块压缩二进制项目格式。ASE / Aseprite 是独立的交换格式。

## 文件布局

所有整数使用小端编码。文件依次为 32 字节文件头和若干分块，第一块必须为 `META`，随后为 `DATA`。

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 8 | 魔数 `MINEPIX\0` |
| 8 | 2 | 容器版本，当前为 1 |
| 10 | 2 | 文件标志，当前为 0 |
| 12 | 4 | 文件头长度，当前为 32 |
| 16 | 8 | 完整文件长度 |
| 24 | 4 | 分块数量，包含 META |
| 28 | 4 | 前 28 字节的 CRC32 |

每块的头长 20 字节：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | ASCII 类型：META / DATA |
| 4 | 4 | 块标志，当前 1 表示 zlib |
| 8 | 4 | 压缩字节数 |
| 12 | 4 | 原始字节数 |
| 16 | 4 | 原始内容 CRC32 |

`META` 解压后为 UTF-8 JSON，包含 `document` 和 `blocks`。图层、帧时长、标签、混合模式、cel 属性、链接、色板、切片和布局相关作品信息留在 document。像素数组的位置使用 `null` 占位。参考板条目和导入参考图层仅保存 `path`、源尺寸和显示变换，`data` 与临时缺失状态不落盘；打开时按路径读取外部文件，缺失保留占位并允许重新定位。无路径的旧嵌入参考板条目在加载时移除；旧嵌入参考图层的数据清空并保留图层结构及位置变换，其他作品内容不变。此清理只改变内存文档，显式保存后才写回磁盘。

blocks 按 DATA 块顺序记录：

- `path`：对应 document 内占位符的 JSON Pointer。
- `kind`：`u32` 为 RGBA 像素整数；`u16` 为16-bit索引像素（小端，每元素2字节）；既有`u8`索引块仍可读取。新的项目保存不生成参考图 DATA 块。
- `count`：像素元素数量或字节数量。

像素不再以 JSON 数字字符串保存。每个 cel 独立压缩，便于后续做局部读取；当前实现完整加载文档。CRC32 用于损坏检测，不用于身份验证。

## 边界与版本

文件和累计解压数据分别限制为 512 MiB。读取时检查魔数、版本、长度、块标志、校验和、映射和数据长度。未知版本明确拒绝，避免静默丢失内容。

编辑器不再设置固定的 32M 总像素预算：画布、帧层组合、cel 源图及外部参考图不再按此阈值拒绝打开或编辑。画布宽高需为可精确表示的正整数，最多 64 层、256 帧；cel 位置和尺寸仍遵循现有字段范围。实际可处理尺寸取决于内存、浏览器画布和目标格式，上述 512 MiB 容器与解压限制保持。图片导入保留原图尺寸，不再按旧预算自动缩小。

地形预览还使用独立的渲染输出预算：格子数乘图块尺寸后最多8M像素、单边8192。此为界面渲染限制，超限预览的合法元数据仍可载入和保存，作品内容不丢弃；面板提示缩小尺寸后继续编辑。

容器版本与编辑器内存对象的版本分开。内存对象只用于前端交互与 Rust 调用，不承诺为对外项目格式。

## 实施与验证

实现位于 src-tauri/src/project.rs，使用 fast 压缩级别。验证命令见 [开发指南](DEVELOPMENT.md)。

正常保存使用独立的原始字节IPC：`MPXSAVE1`八字节标记、u32元数据长度、UTF-8 `{document,blocks,name,saveAs}`、顺序拼接的原始像素块。前端直接从当前文档对象打包，只序列化小元数据，不再先生成 / 解析整作品JSON；Rust仅解析小元数据，借用payload直接压缩，不再为每个像素建立JSON Value。打包不修改源文档或链接cel共享关系；字符串输入保留用于既有诊断，性能报告明确区分这两条参数准备路径。此IPC不是磁盘文件格式，对外仍是上述PIX v1。底层像素传输保持既有编码；参考图不再加入 payload，仅保存路径元数据。中文目标名称、取消和失败不覆盖沿用原语义。

正常PIX读取先返回实际路径描述符，再由Rust专用命令读取并共用原容器校验，成功后才更新最近记录。响应为`MPXREAD1`八字节标记、u32小JSON元数据长度、UTF-8 `{document,blocks,info?}`以及顺序原始像素块；没有新磁盘版本。前端正常桌面读取解包为定长像素缓冲，通过file.document直接交给模型标准化。file.data仅为按需生成的诊断JSON，正常打开 / 最近缩略图不访问；缩略图读取也不重排最近记录。原生打开、启动队列、第二实例和拖入共用此路径，单个损坏启动项目报错后继续处理后续文件。恢复读取复用二进制项目通道；旧文本恢复副本仅在兼容读取时解析。

## PIX 色板文件

色板与项目共用`.pix`后缀，以文件头区分：项目为`MINEPIX\0`，色板为`MPIXPAL\0`。色板文件整数均为小端，8字节魔数后是u16版本。颜色数不超过65,535时使用v1的u16计数、12字节头；更多颜色使用v2的u32计数、14字节头。随后按色槽顺序保存每色4字节RGBA，总长度必须精确匹配头长度加色数乘4；不再限制256项，文件容量上限仍为512 MiB。透明槽、重复颜色和排列顺序均保留，未知版本或不完整文件会拒绝载入。色板文件不会进入最近项目列表。

本机命名色板库沿用原设置键，写入`MPIXLIB2`，条目数量和ID／UTF-8名称／色板数据长度使用u32，不再受原u16字节长度限制；读取已有`MPIXLIB1`及旧JSON库，写回使用新格式。二进制数据以Base64存入WebView设置，仍受本机存储配额限制。预设另存完整色板快照和关联名称、ID，库条目删除不影响已设预设。

ASE／Aseprite 打开也先返回路径描述符，解码后直接生成 `MPXREAD1` 读取包，不经过中间 PIX 容器的压缩／解压。结构及告警使用小元数据（`info.warnings`），RGBA 与索引采用原始字节，不将完整像素数组序列化成 JSON 文本跨 IPC。普通 cel 保留源图边界与独立偏移，缺失的普通 cel 使用最小透明占位；背景和已栅格化瓦片保持原有画布语义。原 ASE 文件不会因打开而写回；只有成功读取才更新最近记录。

ASE新色板块以u32声明容量，完整读取和写入全部色槽，不再截断256项；索引ASE源像素为8-bit，进入编辑器后扩展为Uint16Array。保存时若实际索引或透明槽超过255，则以RGBA写出，颜色按权威索引及色板生成，当前文档不变；否则仍写8-bit索引。非法范围、截断、缺失色槽和总体容量超限仍拒绝。PIX的16-bit索引文档声明`indexed-16`必需特性，旧版会明确拒绝该特性或u16块，避免误读。

## 二进制恢复、导出和窗口消息

MPXDATA1 原始消息由 8 字节魔数、u32 小元数据长度、UTF-8 `{metadata,lengths}` 和顺序字节块组成。恢复写入内含 MPXSAVE1，磁盘 current.recovery／previous.recovery 使用同一 PIX 校验压缩容器，恢复元信息仍为 metadata.json；不把文件名后缀当作编码依据。快照仅引用外部参考路径，恢复时重读源文件，旧 JSON 快照仍可读。

导出参数与窗口对象图使用小型结构描述，像素、图像、历史和大字符串分离为原始块。正常图像编码使用 Blob 字节，不再经 Base64；菜单 ASE 导出和正常 ASE 保存都可直接读取 PackedSave 像素块。窗口通道保留共享引用、TypedArray、Set／Map，按目标窗口授权的一次性凭证读取，成功接收后才移除源文档。

内存中的主像素为Uint32Array、索引为Uint16Array。索引在提交边界为权威数据，渲染直接查色板，RGBA编辑缓存在需要时生成；PIX仍写RGBA和索引，容器版本不变，新增u16块类型。正常ASE二进制读取中`info.indexedSource`表示只携带源8-bit索引像素块，前端扩为16-bit并据色板恢复派生缓冲。详细范围和验证见[数据架构进度](DATA_ARCHITECTURE.md)。

项目读取和窗口迁移在把普通数组或较宽类型数组转为Uint16Array之前，检查每个索引为0–65535整数；越界、负数、小数和空槽直接报错，避免类型转换先截断非法值。色板范围与索引／RGBA一致性仍由文档校验检查。
